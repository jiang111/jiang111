# Emby 反代配置手册

这份手册是**照着执行就能配好**的操作步骤，适合自己 SSH 操作，也适合交给 AI 助手代为配置。
概念和面板用法见 [README](../README.md)。

所有命令都在**目标服务器上用 root 执行**（SSH 登录后运行）。面板操作全部通过本机的面板 API 完成，不需要浏览器。

> **最快的方式：一键脚本**。[`deploy/master.sh`](../deploy/master.sh) 和 [`deploy/node.sh`](../deploy/node.sh)
> 按本手册的步骤自动完成安装、证书、设置、站点、集群、防火墙、收起面板端口和验证，参数用环境变量传入（见脚本开头的说明），
> 可以重复执行。用法见第 5、6 节开头。下面的分步命令用于理解原理、单独调整或排查。

## 0. 给执行者的须知

- **先收集齐第 1 节的信息再动手**，缺什么就问用户，不要猜上游地址、端口、域名。
- **不要把上游地址、面板密码、同步令牌、Cloudflare 令牌、证书私钥写进公开的地方**（Git 仓库、Issue、聊天截图）。
  上游地址是各家服务器要求保密的，本仓库是公开的。
- 每做完一步，用第 8 节对应的命令验证再继续。
- 修改站点用 API 时是**整体替换**：先读出完整站点对象，改字段，再整体提交（见 7.2）。
- 新增站点**必须带 `"enabled": true`**，不带就是停用状态。
- 面板所有写操作都要带请求头 `X-Emby-Proxy: 1`，否则返回 403「请求来源不正确」（防 CSRF）。
- 面板登录 10 分钟内失败 5 次会被限流（返回 429），密码先从 `config.json` 读准再登录。
- 多服务器时，站点和设置**只在主节点上改**；从节点上的修改接口会返回 409。

## 1. 开始前需要收集的信息

| 信息 | 示例 | 说明 |
| --- | --- | --- |
| 每台服务器的公网 IP 和 SSH 登录方式 | `203.0.113.10`，root + 密钥 | IP 必须符合各上游的规则（有的禁日本 IP / 机房 IP） |
| 每台服务器的角色和名称 | `hk-1` 主节点、`tokyo-1` 从节点 | 单台就是「单机」；名称各台不能重复 |
| 服务器是否有 IPv6 | 有 / 没有 | 没有却开启会导致 nginx 检查不通过 |
| 域名 | `example.com`；客户端用 `emby.example.com`，主节点面板用 `master.example.com` | 需已接入 Cloudflare（第 3.1 节） |
| Cloudflare API 令牌和 Zone ID | 见第 3.2 节 | 用于申请证书和管理 DNS 记录；没有的话按 3.2 让用户创建 |
| 证书方式 | ① acme.sh + Cloudflare 令牌自动申请续期（推荐）② 用户提供证书文件 ③ 服务器上已有证书路径 | |
| 每个上游 Emby | 名称、上游地址、要分配的对外端口 | 上游地址就是用户在客户端里原来填的地址 |
| 上游的特殊要求（如果有） | 对方给的 nginx 模板、要求传真实 IP、证书过期 | 对应第 7.3 节 |

## 2. 约定

| 项目 | 约定 |
| --- | --- |
| 安装目录 | `/opt/emby-proxy`，数据 `/opt/emby-proxy/data` |
| 站点对外端口（nginx HTTPS，客户端填） | `8001` 起，每个上游一个 |
| 站点程序端口（只监听本机） | 对外端口 + 10000，即 `18001` 起。**两者不能相同** |
| 客户端访问地址 | `https://emby.example.com:8001` |
| 面板 | 程序 `55660`，配置完成后只监听 `127.0.0.1` |
| 主节点面板 HTTPS | `https://master.example.com:8443` |
| 证书文件 | `/opt/emby-proxy/data/ssl/fullchain.pem`、`privkey.pem` |

## 3. Cloudflare 域名配置

单台和多台服务器都需要：域名的 DNS 由 Cloudflare 管理、一个 API 令牌（申请证书和管理 DNS 记录）、几条 DNS 记录。

### 3.1 把域名接入 Cloudflare（已接入的跳过）

判断是否已接入：Cloudflare 控制台首页能看到这个域名，且状态是「有效 / Active」。

1. 登录 [dash.cloudflare.com](https://dash.cloudflare.com) → 「Domains / 域」→「Onboard a domain / 添加域」，输入根域名 `example.com`（不要带 `emby.`），
   选择自动扫描已有 DNS 记录，计划选 **Free** 即可。
2. 核对扫描出来的记录，缺的补上（原来的网站、邮件记录等）。
3. Cloudflare 会给两个名称服务器（如 `xxx.ns.cloudflare.com`）。到**买域名的注册商**后台：
   - 如果开了 DNSSEC，**先关闭**（否则切换期间域名会解析失败，接入后可以在 Cloudflare 里重新开启）；
   - 把域名的名称服务器（Nameservers / DNS 服务器）改成 Cloudflare 给的两个。
4. 等待生效（通常几分钟到几小时，最长 24 小时），Cloudflare 会发邮件，控制台状态变为「有效」。

验证：

```bash
dig NS example.com +short          # 应返回 Cloudflare 给的两个 *.ns.cloudflare.com
```

### 3.2 创建 API 令牌，记下 Zone ID

1. 控制台右上角头像 →「My Profile / 我的个人资料」→「API Tokens / API 令牌」→「Create Token / 创建令牌」。
2. 模板选「**Edit zone DNS / 编辑区域 DNS**」→「Use template / 使用模板」。
3. 权限保持 `Zone` → `DNS` → `Edit`；「Zone Resources / 区域资源」选 `Include` → `Specific zone` → `example.com`。
   其它保持默认（也可以在「Client IP Address Filtering」里限制只允许你的服务器 IP 使用）。
4. 「Continue to summary」→「Create Token」，**复制令牌**（只显示一次）。
5. 回到域名的「Overview / 概述」页，右侧「API」区域有 **Zone ID / 区域 ID**，复制下来。

在服务器上验证：

```bash
CF_Token="复制的令牌"
CF_Zone_ID="复制的 Zone ID"
curl -sS -H "Authorization: Bearer $CF_Token" https://api.cloudflare.com/client/v4/user/tokens/verify | grep -o '"status": *"[a-z]*"'
# 应输出 "status":"active"
curl -sS -H "Authorization: Bearer $CF_Token" "https://api.cloudflare.com/client/v4/zones/$CF_Zone_ID/dns_records?per_page=1" | grep -o '"success": *[a-z]*'
# 应输出 "success":true（令牌能管理这个域名的 DNS）
```

> 令牌和 Zone ID 只在服务器上和对话中使用，不要写进仓库。acme.sh 申请证书时会把它们保存在服务器的 `~/.acme.sh/account.conf`，用于自动续期。

### 3.3 DNS 记录规划

**所有记录的代理状态都必须是「仅 DNS」（灰色云朵）**：

- 小黄云（代理）只转发 80、443、8443、2053 等少数端口，`8001` 这类端口过不去；
- Cloudflare 的服务条款限制用普通代理传输大量视频；
- 小黄云会让服务器看到的客户端 IP 变成 Cloudflare 的，影响「同一用户固定同一台」。

| 场景 | 类型 | 名称 | 内容 | 代理 | TTL |
| --- | --- | --- | --- | --- | --- |
| 单台 | A | `emby` | 服务器 IP | 仅 DNS | 自动 |
| 多台 | A | `master` | 主节点 IP | 仅 DNS | 自动 |
| 多台 | A | `emby` | 服务器 1 IP | 仅 DNS | 1 分钟 |
| 多台 | A | `emby` | 服务器 2 IP | 仅 DNS | 1 分钟 |
| 多台 | A | `emby` | …每台接流量的服务器一条（主节点接流量也加） | 仅 DNS | 1 分钟 |

- **不要给 `emby` 加 AAAA（IPv6）记录**，除非所有服务器都有 IPv6 且面板开了「同时监听 IPv6」。
  另外，同一个客户端可能时而走 IPv4 时而走 IPv6，两个地址会被当成两个用户分到不同服务器，
  多台服务器时建议 `emby` 只用 IPv4。
- 多台时 TTL 设 1 分钟，摘除故障服务器后几分钟内生效。
- 域名有 CAA 记录的话，必须包含 `letsencrypt.org`，否则 acme.sh 申请证书会失败（没有 CAA 记录则不用管）。
- 「SSL/TLS」页面的加密模式、「始终使用 HTTPS」等设置只对小黄云生效，灰云下不用改。

### 3.4 在控制台添加记录

域名 →「DNS」→「Records / 记录」→「Add record / 添加记录」：

1. Type 选 `A`，Name 填 `emby`，IPv4 address 填服务器 IP；
2. **点一下橙色云朵，让它变成灰色**（显示「DNS only / 仅 DNS」）；
3. TTL：单台选 Auto，多台选 1 min；
4. Save。多台时重复添加，名称都是 `emby`，内容分别是各服务器 IP；再添加 `master` 指向主节点。

### 3.5 用 API 管理记录

在任意一台服务器上（需要 3.2 的令牌和 Zone ID）：

```bash
CF_Token="令牌"; CF_Zone_ID="Zone ID"; DOMAIN=example.com
cf() { curl -sS -H "Authorization: Bearer $CF_Token" -H 'Content-Type: application/json' -X "$1" "https://api.cloudflare.com/client/v4/zones/$CF_Zone_ID/dns_records$2" ${3:+-d "$3"}; }
cf_ok() { python3 -c 'import json,sys;d=json.load(sys.stdin);print("成功" if d.get("success") else "失败: %s" % [e.get("message") for e in d.get("errors") or []])'; }
cf_add() { cf POST "" "{\"type\":\"A\",\"name\":\"$1.$DOMAIN\",\"content\":\"$2\",\"ttl\":${3:-1},\"proxied\":false}" | cf_ok; }
cf_list() { cf GET "?type=A&name=$1.$DOMAIN" | python3 -c 'import json,sys;[print(r["name"],r["content"],"ttl=%s" % r["ttl"],"小黄云(要改成灰云!)" if r["proxied"] else "灰云") for r in json.load(sys.stdin)["result"]]'; }
cf_del() { for ID in $(cf GET "?type=A&name=$1.$DOMAIN&content=$2" | python3 -c 'import json,sys;[print(r["id"]) for r in json.load(sys.stdin)["result"]]'); do cf DELETE "/$ID" | cf_ok; done; }
```

```bash
# 单台
cf_add emby 服务器IP

# 多台（先加 master，从节点要靠它连接主节点）
cf_add master 主节点IP
cf_add emby 服务器1IP 60
cf_add emby 服务器2IP 60

# 查看
cf_list emby                 # 每条一行：名称 IP ttl 灰云

# 某台服务器故障：从 emby 里摘掉；恢复后加回
cf_del emby 故障服务器IP
cf_add emby 故障服务器IP 60
```

需要 `python3`（Debian/Ubuntu 默认有，没有就 `apt install -y python3`）。
`cf_add` / `cf_del` 输出「成功」即可；同名同 IP 的记录已存在时 `cf_add` 会输出「失败: [...already exists...]」，不用重复添加。

### 3.6 验证解析

```bash
dig +short emby.example.com @1.1.1.1      # 单台：一个 IP；多台：每台的 IP 都在
dig +short master.example.com @1.1.1.1    # 主节点 IP
```

证书用 DNS 验证（TXT 记录），不依赖这些 A 记录，申请证书和添加记录的先后顺序不影响。

### 3.7 （可选）自动摘除故障服务器：Cloudflare Load Balancing

免费 DNS 不会检查服务器是否存活，服务器挂了需要按 3.5 手动 `cf_del`。需要自动摘除时可以开通付费的 Load Balancing
（控制台「Traffic → Load Balancing」，按 Cloudflare 当前价格计费）：

1. **Monitor（健康检查）**：类型 HTTPS，端口 `8001`，路径 `/emby/System/Info/Public`，期望状态码 `200`，
   Header 里加 `Host: emby.example.com`。
2. **Pool（源站池）**：把每台服务器的 IP 加为 endpoint，关联上面的 Monitor。
3. **Load Balancer**：主机名 `emby.example.com`，**代理状态关闭（仅 DNS）**，选择上面的 Pool；流量分配可选按地理位置或随机。
4. 创建后删掉原来手动添加的 `emby` A 记录（Load Balancer 会接管这个名字）。

## 4. 面板 API 的用法

在服务器上执行，定义一个 `api` 函数（之后所有面板操作都用它）：

```bash
P=http://127.0.0.1:55660
PW=$(sed -n 's/.*"admin_password": "\(.*\)".*/\1/p' /opt/emby-proxy/data/config.json)
api() { curl -sS -b /tmp/ep.cookie -c /tmp/ep.cookie -H 'X-Emby-Proxy: 1' -H 'Content-Type: application/json' -X "$1" "$P$2" ${3:+-d "$3"}; echo; }
api POST /api/login "{\"password\":\"$PW\"}"     # 应返回 {"ok":true}
```

- 登录有效期 7 天；修改面板密码后要重新登录。
- 查看当前全部状态：`api GET /api/state`。有 `python3` 时可以格式化：`api GET /api/state | python3 -m json.tool`。
- 返回 `{"error":"..."}` 时，内容就是原因（中文）。

## 5. 场景 A：单台服务器

**一键脚本**（DNS 记录按 A0 先加好）：

```bash
curl -fsSL https://raw.githubusercontent.com/jiang111/jiang111/master/emby-proxy/deploy/master.sh -o /root/ep-master.sh
DOMAIN=example.com NODE_NAME=hk-1 PUBLIC_IP=本机IP MASTER_HOST= \
CF_Token=令牌 CF_Zone_ID=ZoneID \
SITES='A服=https://emby-a.example.net
B服=https://emby-b.example.net' \
bash /root/ep-master.sh
```

`MASTER_HOST=`（留空）表示单台，不配置多服务器。下面是脚本做的分步操作。

### A0. DNS 记录

按第 3.3～3.6 节添加一条 `emby` A 记录指向这台服务器（灰云），并用 `dig +short emby.example.com @1.1.1.1` 确认。

### A1. 安装

```bash
curl -fsSL https://get.docker.com | sh                     # 没装 Docker 时
apt install -y nginx || yum install -y nginx                # 没装 nginx 时
systemctl enable --now nginx
bash <(curl -fsSL https://raw.githubusercontent.com/jiang111/jiang111/master/emby-proxy/install.sh)
```

输出里应有「已启动」和「nginx 自动应用：已开启」。然后按第 4 节定义 `api` 并登录。

### A2. 基础设置

```bash
api PUT /api/settings '{"port_bind":"127.0.0.1"}'
api PUT /api/settings '{"nginx_ipv6":true}'               # 仅服务器有 IPv6 时
```

### A3. 证书（三选一）

**① Cloudflare 令牌，acme.sh 申请通配符证书（推荐）**

```bash
curl https://get.acme.sh | sh -s email=you@example.com
export CF_Token="Cloudflare API 令牌"
export CF_Zone_ID="Zone ID"                 # 第 3.2 节；acme.sh 必须同时有令牌和 Zone ID
~/.acme.sh/acme.sh --issue --dns dns_cf -d example.com -d '*.example.com' --server letsencrypt
mkdir -p /opt/emby-proxy/data/ssl
~/.acme.sh/acme.sh --install-cert -d example.com --ecc \
  --fullchain-file /opt/emby-proxy/data/ssl/fullchain.pem \
  --key-file /opt/emby-proxy/data/ssl/privkey.pem
```

程序一分钟内识别到证书。acme.sh 自动续期后，程序自动更新 nginx。

**② 用户提供的证书文件**（先传到服务器上）

```bash
curl -sS -b /tmp/ep.cookie -H 'X-Emby-Proxy: 1' -F cert=@/root/fullchain.pem -F key=@/root/privkey.pem $P/api/cert; echo
# 证书已过期仍要用时加：-F allow_expired=1
```

**③ 服务器上已有的证书路径**（例如 certbot）

```bash
api PUT /api/settings '{"nginx_cert":"/etc/letsencrypt/live/example.com/fullchain.pem","nginx_key":"/etc/letsencrypt/live/example.com/privkey.pem"}'
```

验证：`api GET /api/state` 里 `settings.cert` 显示证书域名和到期时间（①②），或 `settings.nginx_cert` 是填写的路径（③）。

### A4. 添加站点

每个上游一条（端口按第 2 节约定递增）：

```bash
api POST /api/test '{"upstream":"https://emby-a.example.net"}'     # 先测上游，应返回 server_name 和 version
api POST /api/sites '{"name":"A 服","upstream":"https://emby-a.example.net","mode":"port","port":18001,"public_url":"https://emby.example.com:8001","stream_mode":"proxy","enabled":true}'
```

返回 `{"ok":true,"id":"站点ID","error":""}`；`error` 非空说明端口监听失败。上游有特殊要求见 7.3。

### A5. 确认 nginx 已生效

```bash
sleep 20; cat /opt/emby-proxy/data/nginx/reload.log | head -1      # 应为 ok
ss -ltnp | grep -E ':(8001|18001)\b'                                # nginx 在 8001，emby-proxy 在 127.0.0.1:18001
```

### A6. 防火墙

```bash
ufw allow 8001:8010/tcp                                                     # Debian/Ubuntu（启用了 ufw 时）
firewall-cmd --permanent --add-port=8001-8010/tcp && firewall-cmd --reload  # CentOS（启用了 firewalld 时）
```

云服务器的安全组需要用户在控制台放行同样端口（提醒用户）。**不要**放行 18001 这些程序端口。

### A7. 收起面板端口

```bash
sed -i 's/"admin_listen": ":55660"/"admin_listen": "127.0.0.1:55660"/' /opt/emby-proxy/data/config.json
docker restart emby-proxy
sleep 3; ss -ltn | grep 55660                                          # 应只有 127.0.0.1:55660
```

重启后需要重新登录（`api POST /api/login ...`）。最后按第 8 节验证。

## 6. 场景 B：多台服务器负载均衡

**一键脚本**（DNS 记录按 B3 先加好）：先在主节点执行 `deploy/master.sh`（同场景 A，但不要设 `MASTER_HOST=`），
它最后会打印从节点要执行的命令（含同步令牌），到每台从节点上把 `NODE_NAME`、`PUBLIC_IP` 换成那台的执行即可。
两个脚本默认把 `NODE_NAME.DOMAIN` 作为本机直连域名（视频直连用），先给每台加一条同名 A 记录（灰云）只指向它；
解析不到本机 IP 时脚本提示并不启用，也可以用 `DIRECT_HOST=域名` 指定、`DIRECT_HOST=` 关闭。
主节点只做控制（不接用户流量）时加 `SERVE=0`（不用 `PUBLIC_IP`），`emby` 记录不要加它。
下面是脚本做的分步操作。

顺序：每台安装 → 主节点证书和设置 → 主节点添加站点 → Cloudflare DNS → 从节点加入 → 验证。

### B1. 每台服务器安装

每台执行 A1。

### B2. 主节点：证书和设置

在主节点执行：

1. A3 的方式 ①（或 ②）准备证书。**不要用方式 ③**：路径方式不会把证书文件同步给从节点。
2. 基础设置和集群角色：
   ```bash
   api PUT /api/settings '{"port_bind":"127.0.0.1"}'
   api PUT /api/settings '{"nginx_ipv6":true}'           # 仅所有服务器都有 IPv6 时（这项会同步到从节点）
   api PUT /api/cluster '{"role":"master","node_name":"hk-1","advertise_addr":"主节点公网IP","panel_url":"https://master.example.com:8443","sticky":true,"direct_stream":true,"direct_host":"hk-1.example.com"}'
   TOKEN=$(sed -n 's/.*"token": "\(.*\)".*/\1/p' /opt/emby-proxy/data/config.json); echo $TOKEN
   ```
   - `advertise_addr`：主节点也接用户流量（在 `emby` DNS 记录里）时必填；只做控制给空字符串（同时 `"direct_host":""`），
     它就不参与分配，`emby` 记录里也不要有它。节点失联时它不按名字错开、第一个改 DNS
     （失联节点 90 秒没同步就被移出成员列表，其它从节点随之停止探测它，靠主节点来删）。
   - `direct_host`：本机直连域名，DNS 只解析到这台、证书要覆盖它（通配符证书即可）。
     `direct_stream`（视频直连，默认开启）：用户落到非负责节点时，视频请求 302 到负责节点的直连域名，视频只经过一台；
     API 照常转发。没填直连域名的节点不参与 302，落到它负责的用户仍走转发。
   - `balance`（流量均衡，默认开启）：每天凌晨 5 点按各台本月反代流量重算分配权重（`weights`），用得少的分到更多客户端 IP；
     某台还有其它耗流量的服务时用 `"factors":{"节点名":0.5}` 调低它的份额（0.1～10）。
     立即重算：`api POST /api/cluster/rebalance`（会让部分用户换到另一台，上游会看到 IP 变化）。
   - 故障接管（自动改 DNS）：`api PUT /api/cluster '{"role":"master","node_name":"hk-1","advertise_addr":"主节点公网IP","dns_token":"Cloudflare令牌","dns_zone_id":"ZoneID","dns_name":"emby.example.com"}'`。
     保存前会用令牌查一次 `emby` 的 A 记录，不通过返回原因；令牌同步给各节点，只给该域名的 DNS 编辑权限。`"dns_token":""` 关闭。
     一键脚本带了 `CF_Token`、`CF_Zone_ID` 时自动开启（`DNS_FAILOVER=0` 关闭）。
   - 记下 `TOKEN`，从节点要用。
3. A4 添加站点。
4. A7 收起面板端口（主节点面板之后通过 `https://master.example.com:8443` 访问；SSH 上仍用 `http://127.0.0.1:55660`）。

### B3. Cloudflare DNS

按第 3.3～3.6 节添加 `master` 和 `emby` 记录（`emby` 每台接流量的服务器一条，TTL 60，灰云），并确认解析生效。
视频直连还要给每台加一条直连域名（如 `hk-1`、`tokyo-1`，各自只指向那台，灰云）。
**`master` 记录要在 B4 之前生效**，从节点靠它连接主节点。

### B4. 从节点加入

在每台从节点执行（先按第 4 节登录）：

```bash
api PUT /api/cluster "{\"role\":\"node\",\"node_name\":\"tokyo-1\",\"master_url\":\"https://master.example.com:8443\",\"token\":\"主节点的TOKEN\",\"direct_host\":\"tokyo-1.example.com\"}"
sleep 5; api GET /api/state | grep -o '"status":{[^}]*}'          # last_ok 有值、没有 error 即同步成功
```

- 从节点多 IP 或在 NAT 后面时加 `"advertise_addr":"它的公网IP"`。
- 然后 A6 防火墙、A7 收起面板端口。

### B5. 主节点确认

在主节点：

```bash
api GET /api/state | python3 -c "import json,sys;c=json.load(sys.stdin)['cluster'];print('节点:',[(n['name'],n['addr'],n['current']) for n in c['nodes']]);print('参与分配:',c['members'])"
```

每个从节点 `current` 为 `True`；「参与分配」列出所有接流量的服务器。

流量均衡：

```bash
api GET /api/state | python3 -c "import json,sys;c=json.load(sys.stdin)['cluster'];print(c['traffic']);[print(n) for n in c.get('balance_nodes',[])]"
```

每台 `reported` 为 `True`、`bytes` 是该台本月反代流量，`weight` 是当前权重（每天凌晨 5 点更新，全为 1 表示五五开）。

故障接管（每台都可以查，看到的是它探测其它节点的结果）：

```bash
api GET /api/state | python3 -c "import json,sys;f=json.load(sys.stdin)['cluster']['failover'];[print(p) for p in f['peers']];print('DNS:',f['dns'],f.get('dns_name'),f.get('dns_err',''));[print(l) for l in f.get('dns_log',[])]"
```

每个节点 `down` 为 `False`；开了自动改 DNS 时 `in_dns` 为 `True`（开启后 5 分钟内会核对一次）。

统计汇总：从节点每 10 秒向主节点上报统计，主节点 `/api/state` 的每个站点多出 `cluster_stats`（本机 + 各在线节点之和）
和 `node_stats`（各节点拆分），顶层 `cluster_stats_nodes` 列出上报过的节点、最后上报时间和是否计入（`online`，45 秒内上报过）：

```bash
api GET /api/state | python3 -c "import json,sys;d=json.load(sys.stdin);print([(n['name'],n['online']) for n in d.get('cluster_stats_nodes',[])])"
```

从节点长期不出现在这里：多半是主节点版本较旧（从节点日志里有一次「不支持统计汇总」提示），升级主节点即可。
统计口径：播放按「客户端 IP + 片子」去重（同一 NAT 后多台设备看同一部片子算 1 个）；转发给负责节点的请求只在负责节点计数，
转发这一段单独记为 `relay_requests` / `relay_bytes`（面板「节点间转发」）。

### B6. 防火墙

- 每台：放行站点对外端口（A6），服务器之间的转发也走这些端口。
- 主节点：另外放行 8443（`ufw allow 8443/tcp`）。更稳妥是只对从节点和用户自己的 IP 放行。

### B7. 主节点换到另一台

例如把主节点从 hk-1 换到一台只做控制的新服务器 ctl，hk-1 改成从节点。站点、令牌、面板密码都沿用，从节点不用动。

1. ctl 执行 A1 安装（ARM 服务器也一样，`install.sh` 在本机编译镜像），然后 `docker stop emby-proxy`。
2. 把 hk-1 的 `/opt/emby-proxy/data/config.json`、`account.key`（有站点账号时）和 `ssl/` 拷到 ctl 的同一位置（**不要**拷 `traffic.json`、`stats.json`，
   那是 hk-1 自己的计数），`docker start emby-proxy`，按第 4 节登录（密码也是 hk-1 的）。
3. ctl 改名并改成只做控制（角色不变，令牌保留）：
   ```bash
   api PUT /api/cluster '{"role":"master","node_name":"ctl","advertise_addr":"","direct_host":"","panel_url":"https://master.example.com:8443"}'
   ```
   在 ctl 按 A3 ① 装 acme.sh 申请证书，以后由它续期并同步给各节点；放行 8443（B6）。
4. `master` 记录改指 ctl（先把 TTL 改成 60）。从节点按域名连接主节点，解析生效后自动连到 ctl。
5. hk-1 改成从节点，并去掉面板 HTTPS 地址和它自己的证书续期：
   ```bash
   api PUT /api/cluster "{\"role\":\"node\",\"node_name\":\"hk-1\",\"advertise_addr\":\"hk-1公网IP\",\"master_url\":\"https://master.example.com:8443\",\"token\":\"原TOKEN\",\"direct_host\":\"hk-1.example.com\",\"panel_url\":\"\"}"
   ~/.acme.sh/acme.sh --remove -d example.com --ecc
   ```
6. 在 ctl 按 B5 确认：各节点 `current` 为 `True`，「参与分配」只有接流量的服务器。

## 9. 故障排查

```bash
docker logs --tail 100 emby-proxy                       # 程序日志（监听失败、同步失败、发现推流域名）
cat /opt/emby-proxy/data/nginx/reload.log               # 第 1 行 ok/fail，第 4 行起是 nginx -t 输出
nginx -t                                                # nginx 当前配置检查
systemctl status emby-proxy-nginx.timer                 # 自动应用定时器
api GET '/api/logs?limit=50'                            # 访问日志（status、err、node 字段）
api GET /api/nginx                                      # 程序生成的 nginx 配置
```

| 现象 | 处理 |
| --- | --- |
| `reload.log` 为 fail：`Address family not supported` | 服务器没有 IPv6：`api PUT /api/settings '{"nginx_ipv6":false}'`（多服务器在主节点执行） |
| `reload.log` 为 fail：`cannot load certificate` | 证书路径不对或文件不存在；检查 A3 |
| `reload.log` 为 fail：`Address already in use` | 对外端口被其它程序占用，或和程序端口相同；换端口 |
| 生成的 nginx 配置里有「跳过：请在站点…填写」 | 站点缺 `public_url`，按 6.2 补上 |
| 站点 `status` 为 `error`、`端口监听失败` | 程序端口被占用；换端口 |
| `/api/test` 返回「被重定向到 …」 | 上游拦了本机 IP 或 UA；服务器 IP 不符合对方规则时只能换服务器 |
| `/api/test` 证书错误 | 6.3 的 `ignore_expired` / `insecure_tls` |
| 播放日志 403 | 多为上游的 IP 规则；或推流域名未被允许（查看 `stream_hosts`） |
| 从节点 `status.error` 连接失败 | 从节点上 `curl -sS https://master.example.com:8443/api/cluster/sync` 应返回「同步令牌不正确」的 JSON；不通则查 DNS、8443 防火墙、主节点 `panel_url` |
| 从节点 `status.error` 令牌不正确 | 主节点令牌被重新生成过，重新执行 B4 |
| 日志 `node` 为「→ X 失联，本机处理」 | 本机连不上 X 的对外端口：查 X 的防火墙、nginx、`advertise_addr` |
| 故障接管里节点一直「失联」但它其实正常 | 在本机执行 `curl -sS --resolve emby.example.com:8001:X的IP https://emby.example.com:8001/__emby_proxy/health` 应返回 `ok`；不通查 X 的防火墙、nginx |
| `dns_err` 有内容 | Cloudflare 令牌失效或权限不够（需要该域名的 DNS 编辑权限），在主节点重新填写 |
| 日志有「⇢ X 直连」但播放失败 | 客户端连不上 X 的直连域名：`curl -sS https://X的直连域名:8001/emby/System/Info/Public` 检查 DNS、证书、防火墙；播放器不支持 302 时主节点关闭「视频直连」 |
| 面板登录 429 | 10 分钟后再试；密码从 `config.json` 读取 |

## 10. 参考：字段和接口

### 10.1 config.json

位于 `/opt/emby-proxy/data/config.json`（权限 600）。一般通过 API 修改；直接改文件后要 `docker restart emby-proxy`。

| 字段 | 说明 | 多服务器同步 |
| --- | --- | --- |
| `listen` | 入口端口（路径 / 域名模式），默认 `:55661` | 否 |
| `admin_listen` | 面板端口，默认 `:55660`，建议 `127.0.0.1:55660` | 否 |
| `admin_password` | 面板密码 | 否 |
| `secret` | 面板登录签名密钥 | 否 |
| `cluster_secret` | 推流地址和节点间转发的签名密钥 | 是 |
| `entry_url` / `public_host` | 仅面板显示用 | 是 |
| `port_bind` | 站点程序端口的监听地址，`127.0.0.1` = 仅本机 | 是 |
| `nginx_cert` / `nginx_key` | 证书路径；为空且 `data/ssl/` 有证书时自动使用后者 | 是 |
| `nginx_ipv6` | nginx 同时监听 IPv6 | 是 |
| `panel_url` | 本机面板 HTTPS 地址，填写后生成面板的 nginx 配置 | 否 |
| `cluster.role` | `""` 单机 / `master` / `node` | 否 |
| `cluster.token` | 主节点：同步令牌；从节点：主节点的令牌 | 否 |
| `cluster.master_url` | 从节点：主节点面板地址 | 否 |
| `cluster.node_name` | 本机名称，各台唯一（空则用主机名） | 否 |
| `cluster.advertise_addr` | 本机公网 IP，供其它节点转发；从节点空则用主节点看到的 IP | 否 |
| `cluster.sticky` | 同一用户固定同一台 | 主节点设置，同步给从节点 |
| `cluster.direct_stream` | 视频直连：视频请求 302 到负责节点的直连域名 | 主节点设置，同步给从节点 |
| `cluster.direct_host` | 本机直连域名（只解析到本机，证书覆盖），自动加到站点 nginx 的 `server_name` | 否 |
| `cluster.balance` | 流量均衡：每天凌晨 5 点按各台本月反代流量重算权重 | 主节点 |
| `cluster.weights` | 各节点当前权重（自动计算，随节点列表下发） | 主节点自动维护 |
| `cluster.factors` | 各节点手动系数（0.1～10，该台有其它耗流量的服务时调低） | 主节点 |
| `dns` | 故障接管自动改 DNS：`token`（Cloudflare 令牌）、`zone_id`、`name`（客户端域名） | 主节点设置，同步给从节点 |
| `members` | 从节点：主节点下发的参与分配节点列表 | 是 |
| `sites` | 站点列表，见 10.2 | 是 |
| `accounts` | 站点账号：站点 ID → 密文（AES-256-GCM，密钥在同目录的 `account.key`）。不要手改 | 否（从节点收到同步时清空） |

### 10.2 站点字段

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `id` | 字符串 | 新增时自动生成 |
| `name` | 字符串 | 必填 |
| `enabled` | 布尔 | **新增时要显式给 `true`** |
| `upstream` | 字符串 | 上游地址；只写域名补 `https://`，IP 或非 443 端口补 `http://` |
| `mode` | `port` / `path` / `host` | 接入方式，推荐 `port` |
| `port` | 数字 | `mode=port` 时的程序端口 |
| `path` | 字符串 | `mode=path` 时的路径前缀（不带 `/`） |
| `host` | 字符串 | `mode=host` 时绑定的域名 |
| `public_url` | 字符串 | 客户端访问地址，如 `https://emby.example.com:8001`；生成 nginx 配置和多服务器转发依赖它 |
| `stream_mode` | `proxy` / `direct` | 推流经本机中转 / 客户端直连 |
| `stream_hosts` | 字符串数组 | 允许中转的推流域名（自动学习，可手动加，支持 `*.example.com`） |
| `forward_ip` | 布尔 | 传客户端真实 IP 给上游 |
| `insecure_tls` | 布尔 | 完全不校验上游证书 |
| `ignore_expired` | 布尔 | 上游证书过期仍连接（仍校验域名和签发链） |
| `user_agent` | 字符串 | 覆盖 UA，一般留空 |
| `headers` | 对象 | 自定义请求头，值支持 `{public_base}` `{public_origin}` `{client_ip}`；值为空表示删除该头 |
| `routes` | 数组 | `[{"path":"/xxx","target":"https://{arg.名称}.example.net"}]` |
| `remark` | 字符串 | 备注 |

### 10.3 面板 API

除登录和同步接口（`/api/cluster/sync`、`/api/cluster/report`）外都需要登录 Cookie；除 GET 外都需要请求头 `X-Emby-Proxy: 1`。

| 方法和路径 | 请求体 | 说明 |
| --- | --- | --- |
| `POST /api/login` | `{"password"}` | 登录，返回 Cookie |
| `POST /api/logout` | | 退出 |
| `GET /api/state` | | 全部状态：`settings`（含证书信息 `cert`）、`sites`（含 `stats`、`status`、`error`；主节点另有 `cluster_stats`、`node_stats`）、`nginx`（自动应用状态）、`cluster`、`version`；主节点另有 `cluster_stats_nodes` |
| `GET /api/logs?site=&limit=` | | 访问日志，最新在前，最多 1000 条 |
| `POST /api/test` | `{"upstream","insecure_tls","ignore_expired","user_agent"}` | 测试上游，返回 `ok`、`server_name`、`version`、`ms` 或 `error` |
| `POST /api/sites` | 站点对象 | 新增，返回 `id` |
| `PUT /api/sites/{id}` | 完整站点对象（可带 `stream_hosts_base`） | 整体替换。`stream_hosts_base` 是读取时的推流域名列表，用于保留之后新学到的域名 |
| `DELETE /api/sites/{id}` | | 删除 |
| `PUT /api/sites/{id}/account` | `{"username","password"}` | 保存站点的 Emby 账号（整体替换）。登录后 `/api/state` 的站点里有 `account.username`、`account.password`。从节点返回 409 |
| `DELETE /api/sites/{id}/account` | | 删除站点账号（删除站点时自动删除） |
| `POST /api/sites/{id}/clear-stats` | | 清零累计统计（请求、流量、错误、节点间转发、流量曲线）；主节点上同时以各节点当前上报值为起点 |
| `PUT /api/settings` | `entry_url` `public_host` `port_bind` `nginx_cert` `nginx_key` `nginx_ipv6` `old_password`+`new_password`（只传要改的） | 修改设置，先整体校验再应用 |
| `POST /api/cert` | multipart：`cert`、`key`，可选 `allow_expired=1` | 上传证书 |
| `GET /api/nginx` | | 生成的 nginx 配置（文本） |
| `GET /api/export` | | 导出 JSON |
| `POST /api/import` | `{"mode":"merge"\|"replace","data":导出内容}` | 导入，整体校验，失败不改动 |
| `POST /api/cluster/rebalance` | | 主节点按本月用量立即重算权重 |
| `GET /__emby_proxy/health`（站点端口） | | 健康检查，返回 `ok`；节点间探测用 |
| `PUT /api/cluster` | `role` `node_name` `advertise_addr` `direct_host` `panel_url` `sticky` `direct_stream` `balance` `factors` `dns_token` `dns_zone_id` `dns_name`（主节点）`master_url` `token`（从节点）`new_token`（主节点重新生成令牌） | 集群设置 |
| `POST /api/cluster/sync-now` | | 从节点立即同步 |

### 10.4 宿主机上的组件

| 组件 | 说明 |
| --- | --- |
| Docker 容器 `emby-proxy` | `network_mode: host`，数据卷 `/opt/emby-proxy/data:/data`，环境变量 `HOST_DATA_DIR=/opt/emby-proxy/data` |
| `/opt/emby-proxy/nginx-reload.sh` | 配置变化时复制为 `applied.conf`，`nginx -t` 通过则 reload，否则回滚 |
| `emby-proxy-nginx.timer` | 每 15 秒运行一次上面的脚本 |
| `/etc/nginx/conf.d/emby-proxy.conf` | 软链接到 `/opt/emby-proxy/data/nginx/applied.conf` |
| 环境变量 `EMBY_PROXY_NO_NGINX=1` | 安装时设置则不接管 nginx |
